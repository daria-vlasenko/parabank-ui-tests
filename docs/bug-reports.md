## DEF-001

| Атрибут | Значение |
|---|---|
| **Идентификатор** | DEF-001 |
| **Краткое описание** | Выполняется вход в систему при вводе несуществующего логина на странице входа |
| **Воспроизводимость** | Всегда |
| **Важность** | Критическая |
| **Срочность** | Наивысшая |
| **Симптом** | Некорректная операция |
| **Возможность обойти** | Нет |
| **Требование** | ЧЛ-1.6 |
| **Модуль / подмодуль** | Аутентификация / Форма входа |
| **Окружение** | `https://parabank.parasoft.com/parabank/`, Chrome 152.0.7977.83, Windows 11 |
| **Дата обнаружения** | 15.09.2026 |
| **Статус** | Открыт |

### Подробное описание

Приложение не выполняет сверку введённых учётных данных с хранилищем. При вводе логина, отсутствующего в системе, и произвольного пароля выполняется вход: открывается страница обзора счетов, клиенту доступны операции со счетами.

При повторном выполнении шагов с теми же учётными данными открывается счёт с другим номером — сессия связывается с произвольным счётом.

Проверка на заполненность полей выполняется корректно: при отправке формы с пустыми полями вход не выполняется и отображается сообщение «Please enter a username and password.»

**Фактический результат:** выполняется переход на `overview.htm`, отображается страница «Accounts Overview» со счётом и остатком `$515.50`.

**Ожидаемый результат:** выполняется переход на `login.htm`, отображается сообщение «The username and password could not be verified.», вход не выполняется.

Требования к учебному стенду не опубликованы; ожидаемый результат сформулирован на основании текста сообщения, реализованного в самом приложении.

### Шаги по воспроизведению

1. Открыть `https://parabank.parasoft.com/parabank/logout.htm` для завершения активной сессии.
2. Открыть `https://parabank.parasoft.com/parabank/index.htm`.
3. В поле «Username» ввести `no_such_user_12345`.
4. В поле «Password» ввести `wrong_password`.
5. Нажать кнопку «Log In».

Выполняется переход на `overview.htm`, отображается заголовок «Accounts Overview» и таблица со счётом; в левой панели отображается меню авторизованного клиента со ссылками «Open New Account», «Transfer Funds», «Bill Pay».

### Обоснование важности

Дефект представляет собой полный обход аутентификации в приложении банковской предметной области: доступ к счёту и операциям с денежными средствами предоставляется без подтверждения личности. Обходной путь для пользователя отсутствует, ограничение доступа средствами приложения не выполняется.

Классификация: OWASP Top 10 — A07 Identification and Authentication Failures; CWE-287 Improper Authentication; частный случай CWE-306 Missing Authentication for Critical Function.

### Приложения

Снимок экрана страницы `overview.htm` после выполнения шагов 1–5 — в отчёте Allure прогона от 15.09.2026, тест `LoginTests`, вложение «Screenshot».

### Комментарий

ParaBank — учебный демонстрационный стенд Parasoft; часть дефектов в нём заложена намеренно. Заключение ограничено зафиксированным поведением приложения; утверждение о непреднамеренности дефекта не делается.

Сценарий ЧЛ-1.6 в набор автотестов не включён до исправления дефекта. В набор включён сценарий входа с незаполненными полями (ЧЛ-1.2), выполняющийся на стенде корректно.

## DEF-002

| Атрибут | Значение |
|---|---|
| **Идентификатор** | DEF-002 |
| **Краткое описание** | Выполняется перевод суммы, превышающей доступный остаток счёта-источника |
| **Воспроизводимость** | Всегда |
| **Важность** | Высокая |
| **Срочность** | Высокая |
| **Симптом** | Некорректная операция |
| **Возможность обойти** | Нет |
| **Требование** | ЧЛ-3.4 |
| **Модуль / подмодуль** | Переводы / Перевод между счетами |
| **Окружение** | `https://parabank.parasoft.com/parabank/`, Chrome 153.0.8010.54, Windows 11 |
| **Дата обнаружения** | 27.09.2026 |
| **Статус** | Открыт |

### Подробное описание

Приложение не выполняет проверку достаточности средств на счёте-источнике. При указании суммы перевода, превышающей доступный остаток, операция выполняется: средства списываются в полном объёме, баланс счёта-источника принимает отрицательное значение.

Сообщение об ошибке не отображается: блок `#showError` остаётся скрытым и пустым. Отображается страница подтверждения «Transfer Complete!» с указанием запрошенной суммы.

**Фактический результат:** перевод выполняется, отображается сообщение «$1415.50 has been transferred from account #15120 to account #15231», баланс счёта-источника принимает значение `-$1000.00`.

**Ожидаемый результат:** перевод отклоняется, отображается сообщение о недостаточности средств, балансы обоих счетов остаются неизменными.

Требования к учебному стенду не опубликованы; ожидаемый результат сформулирован на основании общих правил предметной области: списание сверх остатка без оформленного договора овердрафта не допускается.

### Шаги по воспроизведению

1. Зарегистрировать нового клиента через `https://parabank.parasoft.com/parabank/register.htm`.
2. Открыть второй счёт через «Open New Account», тип «SAVINGS».
3. Открыть «Accounts Overview» и зафиксировать баланс счёта-источника — `$415.50`.
4. Открыть «Transfer Funds».
5. В поле «Amount» ввести сумму, превышающую зафиксированный остаток на 1000 — `1415.50`.
6. В списке «From account» выбрать счёт-источник, в списке «To account» — второй счёт.
7. Нажать кнопку «Transfer».
8. Открыть «Accounts Overview» и проверить баланс счёта-источника.

После шага 7 отображается заголовок «Transfer Complete!» и текст с суммой перевода. После шага 8 баланс счёта-источника отображается как отрицательный.

### Обоснование важности

Дефект относится к операциям с денежными средствами в приложении банковской предметной области. Клиенту предоставляется возможность распорядиться средствами, которые на счёте отсутствуют, без проверки лимита и без оформления договора овердрафта. Обходной путь для пользователя отсутствует, ограничение средствами приложения не выполняется.

В отличие от DEF-001, дефект не относится к нарушениям контроля доступа: нарушено бизнес-правило предметной области, а не механизм аутентификации или авторизации.

### Комментарий

ParaBank — учебный демонстрационный стенд Parasoft; часть дефектов в нём заложена намеренно. Заключение ограничено зафиксированным поведением приложения.

Заведомо падающий тест в набор не включается — красный результат без привязки к заведённому дефекту снижает доверие к прогону. При исправлении дефекта тест покраснеет и зафиксирует изменение поведения.
