# Найденные дефекты

---

## DEF-001. Приложение принимает любые учётные данные

| | |
|---|---|
| **Severity** | Critical |
| **Priority** | Highest |
| **Компонент** | Аутентификация |
| **Окружение** | `https://parabank.parasoft.com/parabank/`, Chrome 152, Windows 11 |
| **Дата обнаружения** | 15.09.2026 |
| **Как найден** | падение автотеста `LoginTests.showsErrorForUnknownUser` |

### Шаги воспроизведения

1. Открыть `https://parabank.parasoft.com/parabank/index.htm`
2. Убедиться, что сессия не активна (при необходимости перейти на `logout.htm`)
3. В поле `Username` ввести `no_such_user_12345`
4. В поле `Password` ввести `wrong_password`
5. Нажать `Log In`

### Ожидаемый результат

Переход на `login.htm`, сообщение «The username and password could not be verified.», пользователь не авторизован.

### Фактический результат

Переход на `overview.htm`. Пользователь авторизован, открыта страница «Accounts Overview» с существующим счётом и балансом `$515.50`.

При повторении с теми же данными номер счёта каждый раз другой (наблюдались `17340`, `13677`) — система выдаёт сессию с произвольным счётом.

### Дополнительная проверка

Пустые логин и пароль система отклоняет корректно: переход на `login.htm`, заголовок `Error!`, сообщение «Please enter a username and password.»

**Вывод:** проверка на заполненность полей реализована, сверка учётных данных с хранилищем — нет.

### Классификация

- **OWASP Top 10: A07** — Identification and Authentication Failures
- **CWE-287** — Improper Authentication
- частный случай **CWE-306** — Missing Authentication for Critical Function

### Обоснование severity

Полный обход аутентификации в банковском приложении: любой пользователь получает доступ к счёту и операциям с деньгами без подтверждения личности.

### Оговорка

ParaBank — учебный демонстрационный стенд Parasoft, часть дефектов в нём заложена намеренно. Вывод ограничен зафиксированным поведением системы; утверждение о непреднамеренности дефекта не делается.

### Решение по автотесту

Сценарий с неверным паролем **не включён** в регрессионный набор: заведомо красный тест без привязки к заведённому дефекту создаёт шум, на который команда перестаёт реагировать.

В наборе оставлен негативный сценарий на пустые поля, который на этом стенде отрабатывает корректно. Найденное поведение зафиксировано настоящим баг-репортом.

**Важно:** ожидание не было переписано под фактическое поведение ради зелёного прогона. Такая правка превращает автотест из инструмента обнаружения дефектов в инструмент их фиксации.
