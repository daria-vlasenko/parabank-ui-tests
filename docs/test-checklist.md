Идентификаторы пунктов (ЧЛ-N.N) используются для ссылок из тест-кейсов и отчётов о дефектах.

## Шкала важности

| Градация | Содержание |
|---|---|
| Критическая | потеря или неверное списание денежных средств, доступ к данным другого клиента |
| Высокая | недоступен основной пользовательский путь, обходной путь отсутствует |
| Средняя | функция работает неверно, обходной путь существует |
| Низкая | неудобство, на достижение цели пользователем не влияет |

## Обозначения покрытия

| Значение | Содержание |
|---|---|
| `Автотест: <класс>.<метод>` | покрыто автоматизированным тестом |
| `Вручную: ТК-NN` | выполняется вручную по тест-кейсу |
| `Не автоматизирован` | автотест отсутствует |
| `Исключён: DEF-NNN` | из набора исключён, причина — дефект |
| `Фиксирует дефект: DEF-NNN` | автотест в наборе, проверяет фактическое поведение при известном дефекте |
| `Уровень API` | проверка выполняется на уровне API |

## Принцип отбора проверок для автоматизации

Автотест на уровне UI — дорогой инструмент: написанный один раз, он поддерживается весь срок жизни проекта. Поэтому проверка проходит отбор, а не автоматизируется по умолчанию.

| Куда относится проверка | Критерий |
|---|---|
| **UI-автотест** | сквозной пользовательский путь, высокая цена ошибки, повторяется в каждом регрессе, результат детерминирован |
| **Уровень API** | проверка не требует интерфейса: валидация форматов, округление, поиск по параметрам. Быстрее и стабильнее, чем через браузер |
| **Вручную** | субъективная оценка (вёрстка, тексты), разовый сценарий, комбинаторика значений делает поддержку дороже пользы |

Решение «выполняется вручную» принимается только для проверок, которые остались бы ручными и в рабочем проекте. Проверки, которые в реальной работе автоматизируют на другом уровне, помечены как `Уровень API`, а не как ручные.

Проверка ЧЛ-1.5 этот случай не покрывает.

| ID | Проверка | Важность | Покрытие |
|---|---|---|---|
| ЧЛ-3.1 | Клиент переводит средства между собственными счетами | Критическая | `Автотест: TransferFundsTests.transfersBetweenOwnAccounts` |
| ЧЛ-3.2 | Баланс счёта-источника уменьшается на сумму перевода | Критическая | `Автотест: TransferFundsTests.transfersBetweenOwnAccounts` |
| ЧЛ-3.3 | Баланс счёта-получателя увеличивается на сумму перевода | Критическая | `Автотест: TransferFundsTests.transfersBetweenOwnAccounts` |
| ЧЛ-3.4 | Перевод суммы, превышающей остаток, отклоняется | Критическая | `Фиксирует дефект: DEF-002` |
| ЧЛ-3.5 | Перевод нулевой суммы отклоняется | Средняя | `Уровень API` |
| ЧЛ-3.6 | Перевод отрицательной суммы отклоняется | Высокая | `Уровень API` |
| ЧЛ-3.7 | Сумма перевода с копейками округляется по правилам системы | Средняя | `Уровень API` |

**Примечание к ЧЛ-3.1 — ЧЛ-3.3.** Покрываются одним автотестом: проверка перевода без сверки обоих балансов неполна. Страница подтверждения сообщает о принятии операции, но не о её результате, поэтому тест возвращается в обзор счетов и сверяет фактические балансы до и после.

**Примечание к ЧЛ-3.4.** Проверка выявила дефект DEF-002: перевод сверх остатка выполняется, баланс уходит в минус. Автотест в наборе присутствует в изменённой формулировке — фиксирует фактическое поведение и помечен `@Issue("DEF-002")`. При исправлении дефекта тест покраснеет и зафиксирует изменение.

## 4. Поиск транзакций

Модуль: `Поиск транзакций`.

| ID | Проверка | Важность | Покрытие |
|---|---|---|---|
| ЧЛ-4.1 | Транзакция находится по сумме | Высокая | `Уровень API` |
| ЧЛ-4.2 | Транзакции находятся по диапазону дат | Средняя | `Уровень API` |
| ЧЛ-4.3 | Транзакция находится по идентификатору | Средняя | `Уровень API` |

**Примечание к разделу 4.** Поиск транзакций — проверка логики выборки, а не интерфейса. У ParaBank есть REST API, и проверка на его уровне быстрее и стабильнее: не зависит от разметки, не требует браузера, позволяет проверить больше комбинаций параметров за то же время. Через интерфейс имеет смысл проверить только сам факт отображения результата.
