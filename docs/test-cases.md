# Тест-кейсы

Кейсы для сценариев, **не покрытых автотестами** — обоснование выбора в `test-checklist.md`.

Тестируемая система: [ParaBank](https://parabank.parasoft.com/parabank/index.htm).

---

## TC-01. Регистрация: отправка пустой формы

| | |
|---|---|
| **Приоритет** | High |
| **Техника** | классы эквивалентности (класс «пустое значение») |
| **Предусловия** | пользователь не авторизован, открыта страница `register.htm` |

**Шаги**

1. Не заполнять ни одно поле формы
2. Нажать `Register`

**Ожидаемый результат**

Регистрация не выполнена, пользователь остаётся на странице регистрации. Под каждым обязательным полем отображается сообщение о необходимости заполнения. Учётная запись не создана.

## TC-02. Регистрация: пароль и подтверждение не совпадают

| | |
|---|---|
| **Приоритет** | High |
| **Техника** | классы эквивалентности (валидный / невалидный класс) |
| **Предусловия** | пользователь не авторизован, открыта страница `register.htm` |

**Шаги**

1. Заполнить все поля корректными значениями
2. В поле `Password` ввести `Password123!`
3. В поле `Confirm` ввести `Password124!`
4. Нажать `Register`

**Ожидаемый результат**

Регистрация не выполнена. Отображается сообщение о несовпадении паролей. Учётная запись не создана.

---

## TC-03. Регистрация: граничные значения длины логина

| | |
|---|---|
| **Приоритет** | Medium |
| **Техника** | анализ граничных значений |
| **Предусловия** | известно ограничение на длину логина по требованиям |

**Шаги**

Выполнить регистрацию последовательно с логинами длиной: минимум минус один символ, минимум, минимум плюс один, максимум минус один, максимум, максимум плюс один.

**Ожидаемый результат**

Значения внутри допустимого диапазона принимаются, значения за границей отклоняются с понятным сообщением. Поведение на самих границах соответствует требованиям.

**Примечание.** Ограничения в документации стенда не заданы — требуется уточнение у аналитика. До уточнения кейс считается заблокированным.

## TC-04. Перевод суммы, превышающей остаток

| | |
|---|---|
| **Приоритет** | Critical |
| **Техника** | анализ граничных значений |
| **Предусловия** | пользователь авторизован, открыто не менее двух счетов, остаток на счёте-источнике известен |

**Шаги**

1. Открыть `Transfer Funds`
2. В поле `Amount` ввести сумму, превышающую остаток на счёте-источнике на 0.01
3. Выбрать счёт-источник и счёт-получатель
4. Нажать `Transfer`

**Ожидаемый результат**

Перевод отклонён с сообщением о недостатке средств. Балансы обоих счетов не изменились. Транзакция не появилась в истории операций.

## TC-05. Отображение формы входа на узком экране

| | |
|---|---|
| **Приоритет** | Low |
| **Техника** | тестирование на основе опыта |
| **Предусловия** | открыта главная страница |

**Шаги**

1. Установить ширину окна браузера 360 пикселей
2. Осмотреть форму входа

**Ожидаемый результат**

Поля и кнопка входа видны целиком, не перекрывают друг друга и не выходят за границы экрана. Горизонтальная прокрутка отсутствует. Текст читаем.

## Почему кейсов пять, а не сорок

Набор показывает **формат и подход**, а не претендует на полноту. Полный набор тест-кейсов ведётся в системе управления тестами (TestRail, Qase, Allure TestOps), а не в markdown-файле репозитория: там есть версионирование, привязка к релизам, история прогонов и отчётность.

Здесь — иллюстрация того, как оформляются кейсы и какие техники тест-дизайна применяются при их проектировании.
