# Тест-кейсы

Тест-кейсы для пунктов чек-листа, выполняемых вручную. Основания выбора — в `test-checklist.md`.

Тестируемое приложение: [ParaBank](https://parabank.parasoft.com/parabank/index.htm).

**О поле «Требование».** Требования к учебному стенду Parasoft не опубликованы. В поле указана ссылка на пункт чек-листа; ожидаемые результаты зафиксированы по состоянию приложения на 15.09.2026 и подлежат уточнению при появлении требований.

---

## ТК-01

| Атрибут | Значение |
|---|---|
| **Заглавие** | Регистрация клиента, все поля не заполнены |
| **Приоритет** | Высокий |
| **Требование** | ЧЛ-1.7 |
| **Модуль / подмодуль** | Аутентификация / Форма регистрации |

**Исходные данные**

Пользователь не авторизован.

| Шаги | Ожидаемые результаты |
|---|---|
| 1. Открыть `https://parabank.parasoft.com/parabank/register.htm` | 1. Отображается форма «Signing up is easy!» с незаполненными полями |
| 2. Нажать кнопку «Register», не заполняя поля | 2. Клиент не создан, форма остаётся на экране. Под полями отображаются сообщения: «First name is required.», «Last name is required.», «Address is required.», «City is required.», «State is required.», «Zip Code is required.», «Social Security Number is required.», «Username is required.», «Password is required.», «Password confirmation is required.» |

**Комментарий.** Поле «Phone #» сообщения не выводит — на 15.09.2026 оно не является обязательным. При появлении требований проверить, соответствует ли это ожидаемому поведению.

## ТК-03

| Атрибут | Значение |
|---|---|
| **Заглавие** | Регистрация клиента, граничные значения длины логина |
| **Приоритет** | Средний |
| **Требование** | ЧЛ-1.9 |
| **Модуль / подмодуль** | Аутентификация / Форма регистрации |
| **Статус** | Заблокирован: ограничения длины логина не определены |

**Исходные данные**

Пользователь не авторизован. Из требований получены значения `MIN` и `MAX` — минимально и максимально допустимая длина логина.

| Шаги | Ожидаемые результаты |
|---|---|
| 1. Открыть форму регистрации, заполнить все поля корректными значениями, в поле «Username» ввести логин длиной `MIN − 1` символ, нажать «Register» | 1. Клиент не создан, отображается сообщение о недопустимой длине логина |
| 2. Повторить шаг 1 с длиной логина `MIN` | 2. Клиент создан, отображается страница «Welcome [логин]» |
| 3. Повторить шаг 1 с длиной логина `MIN + 1` | 3. Клиент создан, отображается страница «Welcome [логин]» |
| 4. Повторить шаг 1 с длиной логина `MAX − 1` | 4. Клиент создан, отображается страница «Welcome [логин]» |
| 5. Повторить шаг 1 с длиной логина `MAX` | 5. Клиент создан, отображается страница «Welcome [логин]» |
| 6. Повторить шаг 1 с длиной логина `MAX + 1` | 6. Клиент не создан, отображается сообщение о недопустимой длине логина |

**Комментарий.** Тест-кейс не выполняется до получения значений `MIN` и `MAX`. Ожидаемые результаты сформулированы на основании стандартного поведения при проверке граничных значений и подлежат уточнению.

## ТК-04

| Атрибут | Значение |
|---|---|
| **Заглавие** | Перевод суммы, превышающей остаток на счёте-источнике |
| **Приоритет** | Критический |
| **Требование** | ЧЛ-3.4 |
| **Модуль / подмодуль** | Переводы / Перевод между счетами |

**Исходные данные**

Клиент зарегистрирован и авторизован. Открыто не менее двух счетов. Остаток на счёте-источнике зафиксирован на странице «Accounts Overview».

| Шаги | Ожидаемые результаты |
|---|---|
| 1. Перейти по ссылке «Transfer Funds» | 1. Отображается форма перевода с полями «Amount», «From account #», «To account #» |
| 2. В поле «Amount» ввести сумму, превышающую остаток на счёте-источнике на 0.01 | 2. Введённое значение отображается в поле |
| 3. Выбрать счёт-источник и счёт-получатель, нажать «Transfer» | 3. Перевод не выполнен, отображается сообщение о недостатке средств на счёте |
| 4. Перейти по ссылке «Accounts Overview» | 4. Остатки обоих счетов совпадают со значениями, зафиксированными в исходных данных |

**Комментарий.** Точный текст сообщения на шаге 3 подлежит уточнению при выполнении тест-кейса.

## О составе набора

Набор содержит пять тест-кейсов и не претендует на полноту покрытия. Он демонстрирует применяемый формат и техники проектирования: классы эквивалентности (ТК-01, ТК-02), анализ граничных значений (ТК-03, ТК-04), тестирование на основе опыта (ТК-05).

Полный набор тест-кейсов ведётся в системе управления тестированием (TestRail, Qase, Allure TestOps), где обеспечиваются версионирование, связь с требованиями и выпусками, история выполнения и отчётность.
