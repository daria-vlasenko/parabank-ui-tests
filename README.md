# ParaBank UI Tests

[![CI](https://github.com/daria-vlasenko/parabank-ui-tests/actions/workflows/ci.yml/badge.svg)](https://github.com/daria-vlasenko/parabank-ui-tests/actions/workflows/ci.yml)

UI-автотесты демо-приложения интернет-банка [ParaBank](https://parabank.parasoft.com/parabank/index.htm) — учебного стенда Parasoft для практики тестирования.

Проект — часть портфолио по автоматизации тестирования. Смежные репозитории: [conduit-api-tests](https://github.com/daria-vlasenko/conduit-api-tests) (API, REST Assured), [java-testing-practice](https://github.com/daria-vlasenko/java-testing-practice) (unit, JUnit 5 + Mockito).

> **Статус: в работе.** Реализованы сценарии регистрации и входа, настроены Allure и CI. Остальное покрытие — в плане ниже.

## Стек

| Компонент | Назначение |
|---|---|
| Java 17 | язык |
| Maven | сборка и запуск |
| Selenide 7.9.3 | работа с браузером, умные ожидания |
| JUnit 5 | тестовый движок |
| Allure | отчётность, скриншоты при падении |
| GitHub Actions | прогон в headless-браузере на каждый push |

## Запуск

```bash
mvn clean test                    # прогон с видимым браузером
mvn clean test -Dheadless=true    # прогон без окна браузера
mvn allure:serve                  # собрать отчёт и открыть в браузере
```

Браузер переключается параметром: `-Dbrowser=firefox`. По умолчанию Chrome.

## Найденный дефект

Негативный тест на вход с неверными учётными данными упал. Разбор показал, что **стенд принимает любую непустую пару логин-пароль** и выдаёт авторизованную сессию со случайным счётом. Проверка на заполненность полей работает, сверки с хранилищем учётных данных нет.

| | |
|---|---|
| **Шаги** | открыть `index.htm`, ввести несуществующий логин и произвольный пароль, нажать `Log In` |
| **Ожидалось** | сообщение «The username and password could not be verified.» |
| **Фактически** | переход на `overview.htm`, пользователь авторизован |
| **Severity** | Critical — обход аутентификации в банковском приложении |
| **Классификация** | OWASP A07 Identification and Authentication Failures, CWE-287 |

ParaBank — учебный стенд, часть дефектов в нём заложена намеренно, поэтому вывод ограничен зафиксированным поведением.

**Сценарий не включён в набор:** заведомо красный тест без привязки к дефекту — шум, на который команда перестаёт реагировать. Вместо него в наборе негативный кейс на пустые поля.

## Принятые решения

**Page Object.** Локаторы живут в классах-страницах, в тестах нет ни одного селектора. Правка разметки сайта чинится в одном месте, а не в каждом тесте.

**Page Component.** Левое меню вынесено в отдельный класс `LeftPanel`: оно присутствует на всех страницах после входа, дублировать его в каждом Page Object бессмысленно.

**Уникальные данные вместо фикстур.** `TestDataFactory` генерирует клиента с уникальным логином на каждый прогон. Стенд общий и запоминает регистрации, поэтому фиксированные данные сработали бы ровно один раз.

**Никаких `Thread.sleep`.** Только условия Selenide с перепроверкой до таймаута.

**Поиск по атрибуту вместо экранирования.** У полей формы регистрации идентификаторы содержат точку (`customer.firstName`), а в CSS точка означает класс. Вместо `#customer\\.firstName` используется `input[id='customer.firstName']` — то же самое, но без экранирования и связанных с ним ошибок.

**Java 17, не 25.** На Java 25 не стартует агент AspectJ, из-за чего Allure перестаёт записывать шаги внутри тестов. Версия зафиксирована и локально, и в CI.

**Раздельные версии Allure.** `allure-java` (библиотека) и `allure-commandline` (утилита сборки отчёта) выпускаются независимо, поэтому в `pom.xml` разведены в два свойства.

**Транзитивная зависимость с уязвимостью переопределена.** `commons-lang3` поднят до 3.20.0 через `dependencyManagement` — закрывает CVE-2025-48924.

## Структура

```text
src/main/java/com/parabank/
├── config/
│   └── WebConfig               адрес стенда, таймаут, размер окна, браузер
├── data/
│   ├── NewUser                 запись с данными клиента
│   └── TestDataFactory         генерация уникального клиента
└── pages/
    ├── LoginPage               форма входа, сообщения об ошибках
    ├── RegistrationPage        форма регистрации
    ├── LeftPanel               меню авторизованного пользователя
    └── AccountsOverviewPage    обзор счетов

src/test/java/com/parabank/tests/
├── BaseWebTest                 настройка Selenide, listener Allure, закрытие браузера
├── HomePageTests
├── LoginTests
└── RegistrationTests
```

## CI

При каждом push и pull request в `main` GitHub Actions поднимает Ubuntu, ставит JDK 17 и прогоняет тесты в headless-Chrome.

Результаты Allure сохраняются артефактом прогона всегда, скриншоты Selenide — только при падении. Скачать их можно со страницы конкретного запуска во вкладке `Actions`.
